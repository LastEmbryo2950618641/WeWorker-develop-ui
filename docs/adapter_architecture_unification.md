# Adapter 统一架构与迁移计划

状态：公共架构、v2 内置资产及历史命令兼容已交付实现；真实浏览器重定向、Toolkit 公共最小链路和 Windows 打包已验证。最新验收证据、同事接手方式及剩余人工事项以 `docs/adapter_migration_acceptance.md` 为准；后文保留各历史批次记录，不代表当前仍有同样阻塞。安装/升级、macOS 和真实页面完整生成验收尚未关闭。

## Toolkit 职责与交接边界（2026-09-22）

用户确认：Toolkit 属于 DOM 类 Adapter，并有独立的自动探索能力，由另一位同事负责。DOM/API 描述能力实现方式，Extension/Toolkit 描述执行体系；统一管理不合并 Runner，也不把客户端 API 自动探索等同于 Toolkit 自动探索。

本次架构迁移负责：稳定 v2 包与 manifest 契约、Profile 隔离、安装/注册表/启停/更新、CLI/Backend/Skill/UI 共用发现与调用，以及 Toolkit Runner 的独立路由、参数原样转发、结果/错误处理和 embedded Runtime 资源定位。使用公开占位的最小 Toolkit 测试包验证安装到执行的公共链路，并检查打包后脱离源码的资源边界；相关未验证项仍须明确记录。

同事接手负责：Toolkit 自动探索、DOM 探索策略、生成器输出适配、具体 Toolkit 命令与站点行为，以及这些能力在新架构下的完整业务验收。其新生成产物应遵守统一 v2 包与安装管理契约，不另建注册表或绕过确认门；是否需要任务式草稿等接入改动，由同事依据探索实现评估。

交付时提供：可拉取的明确提交基线、包格式与 Runtime 接口说明、最小测试包及复现命令、已验证矩阵和待办清单。提交基线须在获准推送/合并后才能供同事拉取；目前不因此自动执行推送、合并或发版。

本次完成标准：公共 Toolkit 接入契约和最小执行链路有验证证据，未迁移的探索入口与限制明确交接。Toolkit 自动探索改造及具体业务全流程不作为本次架构迁移的完成前提，也不得被记为已经完成。Windows/macOS 公共安装资源验收仍在本次范围内，不能用源码单测替代。

## 目标与版本边界

本次范围调整（2026-09-21）：扩展内自动探索计划后续下线，不再重构其旧界面和文件编辑器；仅保留必要兼容。客户端 API 自动探索仍须使用统一 v2 草稿、验证、安装链路。已完成的共用生成校验与预览隔离保留。旧扩展编辑入口尚未迁移，不作为本次完整工作台交付目标。

开源版与内网版采用相同的包格式、目录规则、注册表、安装器、生成链路和执行器。版本差异限于 Adapter 资产、服务地址、认证配置和 Profile/Overlay。每阶段同时修改、验证两个仓库，分别通过 PR 进入 develop。内部资产、配置和提交历史不得进入公开仓库。

Adapter 是唯一分发和安装单位。浏览器扩展承担浏览器执行与权限检查；embedded Toolkit Runtime 承担 Toolkit 执行。统一包管理不合并两种 Runner，不改变 WebCLI 不按业务 Schema 转换参数类型的约定。

## 目录与数据所有权

| 内容 | 目标路径 | 所有权与行为 |
|---|---|---|
| 内置源码 | 仓库根 adapters/<name>/ | 维护者通过 Git 管理；Profile/Overlay 选择打包集合 |
| 内置资源 | 应用资源目录 adapters/<name>/ | 构建生成、运行时只读，不被 Hub 更新或生成任务修改 |
| 用户安装 | 公开默认 .weworker/adapters/<name>/；其他 Profile 为 .weworker/adapters/.profiles/<profile>/<name>/ | 安装管理器维护的当前版本副本；手工复制的目录不自动启用或覆盖 |
| 执行快照 | .weworker/adapter-packages/<profile>/<digest>/<name>/ | 持久保存安装内容，注册表固定摘要；更新与卸载不删除运行中使用的旧快照 |
| 开发草稿 | .weworker/adapter-workspaces/<profile>/<workspace-id>/ | 保存基线、草稿与验证信息；不自动加入正常执行清单 |
| 本机安装状态 | .weworker/adapter-state/<profile>/ | 来源、启用选择、更新状态、迁移记录与包摘要；不写入分发包 |
| 下载缓存 | .weworker/adapter-cache/<profile>/ | 可重建缓存，不承担已安装执行快照的持久存储 |

开发者可在任意显式选择的 Git 工作区开发；开发加载必须显式注册，不扫描整个用户目录。现有生成任务记录先保持兼容，工作区路径通过版本化元数据引用，不要求搬动全部历史记录。

路径由宿主统一解析并注入 Backend、Bridge、WebCLI 与 Worker，不能由各进程根据 cwd 或目录是否存在自行猜测。测试使用临时目录；不读取真实用户安装状态。内网与开源的包目录、执行快照、启用状态与 Hub 来源按 profile 隔离，防止同名包互相覆盖。显式覆盖用户目录时，未指定数据根则将状态、快照、草稿和缓存隔离在该目录的 .host-data 下；同一显式安装根拒绝被不同 Profile 同时认领。

## 包、名称与命令契约

2026-10-17 增量：v2 增加独立 `http` runtime，以 `commands[].http.version=1` 明确能力版本，模块路径为 `http/commands/<id>.js`。旧宿主拒绝未知 runtime；Extension/Toolkit 枚举和执行器不变。PUBLIC_API/COOKIE_API 的请求、凭据、权限、打包与验证契约见 [HTTP Adapter](http_adapter_runtime.md)。下文双运行时描述为原迁移基线。

- manifest 为包描述、版本、域名、命令 Schema、风险与权限的唯一源；生成器、加载器、Hub 校验器共用规范。
- name 是稳定调用标识，显示名称和 match 是不同职责。暂不为追求短名批量改名；保留已发布标识，并建立旧名称到新名称的显式映射。
- 调用保持 webcli call <name>.<command-id>。name 包含点号时使用最长已注册名称匹配，不能按最后一个域名段猜测。
- commands[].aliases 可显式保留同包旧命令名（最多 64 个，仅字母、数字、下划线、短横线，不包含包名前缀）。别名与规范 ID 不得冲突；列表保持一个规范命令，帮助和 Skill 展示兼容名。宿主与扩展将别名解析到同一命令、权限及包摘要；停用、损坏或移除后禁止旧副本回退。commands[].legacyNames 可显式声明最多 64 个完整跨包前缀历史调用名；加载器建立全目录唯一索引，CLI、Backend、Bridge、Extension help/call 与 Skill 使用同一规范命令和包摘要。内部已为可确定映射的旧名声明 legacyNames，未能映射到现有 v2 命令的历史名继续保留清单待产品确认。
- Extension API 命令可声明 execution: { type: "api", runtime: "background" }。省略时仍走页面执行；Toolkit 不接受此声明。页面命令升级为后台命令时新增 execution:background 安装权限，且 Bridge 要求扩展协商 adapter_background_v1 能力。
- Extension 前台只读命令可声明 pageRoute: { origin: "https://example.com", pathname: "/items" }，限定当前页面来源。必须是 match 声明的页面主机及准确 HTTP(S) origin/pathname，无查询串或 hash，不扩大权限。普通调用选择唯一匹配页或多个匹配页中的唯一活动页；缺失/歧义报错，不自动导航。Bridge 要求 page_sources_v1；执行 helper 再次核对路由。省略此字段的命令保留原域名路由行为。
- UI_SELECTOR 的 pageWorkflow=true 支持明确查询续接；固定结果路径使用 pageRoute.additionalPaths。参数化详情导航可增加 pageRoute.navigation: { pathname: "/items/:id", pathParameters: [{ segmentIndex: 1, name: "itemId", description: "公开条目 ID" }] }，固定同源目标与完整路径绑定，纳入 page-navigation 安装权限。入口 pathname 可为固定路径或同一目标模板；普通调用匹配入口/详情路由，仍拒绝缺失和歧义。需要 page_navigation_v1，预览与调用都复核契约后只导航一次，读取新主文档并以独立 continuation 返回结果，不重放失败。实际探索命令与限制见 [开发设计](api_exploration_cli_design.md) 的“参数化页面导航”。
- 命令实现与共享实现分开，宿主 Runtime 不重复装入各个包。
- 现有 v2 runtime 枚举 extension/wewright 是兼容输入；产品层使用 Extension/Toolkit。不得无版本约定地改枚举、改工具参数、改变输出格式。
- 名称校验覆盖 Windows 保留名、非法字符、尾随点与空格、大小写碰撞；文件校验覆盖路径穿越、符号链接、目录联接及解压体积限制。
- 共享 Skill 和模型能力说明由有效注册表派生。旧 SKILL、知识文件与场景说明先清点消费者、明确迁移归宿，不能直接删除以满足旧规范。
- 宿主能力版本与包版本分离。不支持的命令 Runtime、协议或能力在启用前明确拒绝，不等到模型调用时才失败。

## 统一注册表与执行

注册表记录 name、version、source、实际根路径、包摘要、命令、权限、启用状态、profile 和来源服务标识。来源与版本不替代内容摘要；来源凭据不得写入 manifest、日志或生成上下文。

CLI、Backend、模型工具目录、扩展、Skill 生成和 UI 使用同一有效快照。扫描错误必须可诊断；一个损坏包应隔离，不应导致所有 Adapter 无法加载。

同名内置版和用户版可以共存，只允许一个版本生效。用户显式安装同名替代版本时记录选择；不改写内置包、不追加 .user 改变调用名。卸载用户版后恢复符合当前 profile 的内置版。不同名称匹配同域名时，可保存候选，但启用必须解决冲突。

安装刷新需要使注册表、工具描述、扩展注入和模型已加载 Skill 一致；不可只刷新磁盘清单。执行中的调用固定到启动时的包摘要，新版本用于后续调用，避免更新时删掉正在执行的资源。CLI list/help/call、客户端列表和页面工具发现必须显示相同有效版本。

2026-09-22 最小事件链：安装器仍以 registry revision 作为唯一提交边界；Bridge 按 Profile 监听状态文件并在 revision 变化后广播 `adapter_state_changed`（携带 profile、previousRevision、revision 与变更 Adapter 名）。Backend 收到后清理目录缓存并同步托管 Skill；Extension 收到后刷新宿主目录与匹配 Tab。该链路覆盖本地、生成和未来 Hub 安装的共同提交边界。客户端重连时收到 `sync: true` 的当前 revision 快照：Backend 全量刷新托管状态，Extension 刷新宿主目录并重载全部匹配 Tab，不虚构漏掉的 Adapter 名。Backend 在托管 Skill 刷新成功后通过既有 SSE 将安全事件字段转发 Renderer；Renderer 主动刷新站点/工具目录。Backend 侧刷新串行排队并对临时 Skill 刷新失败执行两次递增延迟重试；刷新期间的新状态事件会合并为最新 revision，避免快速安装造成刷新队列无限增长。

## 浏览器与权限：先验证，再切换

移出扩展目录涉及执行机制，不是单纯改路径。当前存在向 chrome.scripting.executeScript 传 code 字段的路径；Chrome Scripting API 的注入合同为 files 或 func，这条路径不能作为用户包加载已可用的依据。

第一阶段需在真实 MV3 扩展中完成外部包加载原型：内置与用户包分别验证注册、调用、导航重注入、更新及卸载后的工具清理。方案必须满足实际支持的 Chrome API、isolated world 和 CSP，不能靠 mock 接受未知字段，不能用 func 包装 eval 宣称问题已解决。需明确桌面托管扩展与独立扩展各自支持的加载方式。

如果目标扩展分发方式不允许动态 JavaScript 包，须在格式全面迁移前说明限制并确定宿主执行或声明式能力方案，不能关闭浏览器安全限制掩盖问题。

match 只负责站点匹配；跨域、Cookie、后台请求与页面执行权限必须单独建模，并保留现有 manifest 授权边界。安装和升级检查新增权限，不能把 Hub 下载当作自动授予权限。读写安全门、tab/site/task 绑定及来源校验继续有效。

参考：https://developer.chrome.com/docs/extensions/reference/api/scripting

## 安装、更新和 Hub

所有入口调用同一个安装管理器：Hub 下载、本地包、生成草稿和开发项目安装。流程为校验、暂存、冲突及权限检查、选择启用、切换快照、刷新消费者。上传 Hub 独立于本地安装和启用。

安装记录保存服务标识、包身份、版本和摘要；更新只能从记录的来源获取，不能因切换 Hub 地址把同名包当作同一发行物。官方/用户上传属于发布者属性，内置/用户安装属于本地存放属性，不混用。

需要覆盖并发安装锁、Windows 文件占用、中断恢复、失败后的原版本可用性、降级、卸载和正在执行的命令。已有暂存与备份实现不等于这些场景全部通过。哈希用于完整性，不等于发布者身份认证。

公开版未配置 Hub 时仍可离线使用内置和本地包；网络失败不阻断本地发现或调用。服务地址、凭据存储和认证入口按配置提供，不在通用客户端硬编码内部端点。

## API 自动探索与生成

流程：捕获证据 → 生成计划 → 隔离草稿 → 静态及行为验证 → 本地安装确认 → 注册表刷新；Hub 上传为后续独立动作。

- 保留捕获值隔离、计划指定接口绑定、计划与产物工具集合一致性、模型配置隔离、输出耗尽暂停与恢复预算等既有修复。
- scaffold、Agent 写文件、修订、恢复和快速生成均直接产出目标包格式，不保留两套默认输出。
- API 证据、草稿和验证报告按任务隔离，不装入分发包；真实凭据、响应样本与捕获原文不得进入源码、manifest 或测试 Fixture。
- 验证使用统一执行器和任务专属注册表，固定 tab/site/task/包摘要，不覆盖正常运行的 Adapter；测试完成和失败均清理临时注册。
- 修改已有包时记录来源、版本与摘要；安装前核对基线，检测并发更新，不能覆盖期间安装的新版本。
- 旧任务恢复必须识别产物格式和源路径。无法无损升级时明确提示，保留原任务与证据，不静默重建或重新执行网站写操作。
- UI 和协议区分“安装并启用”与“上传到 Hub”，现有 publish 状态不能继续含混使用。
- mock 验证、真实只读验证、真实写操作验证分别报告。沿用用户授权边界，不用 mock 通过替代端到端验收。

## 历史迁移与打包

先建立旧 ID、命令、目录、格式和消费者的映射，再切换。旧目录在验证完成前作为只读兼容输入，不继续新增产物。禁止因新版用户目录为空自动切换到其他历史目录而改变生效集合。

旧用户包、内置修改、Toolkit Skill 目录和未完成草稿需分别识别；先输出可审阅的迁移清单与冲突，不自动合并、覆盖或删除。停用兼容读取与删除旧源码是独立阶段。

开发启动、桌面安装包、独立 WebCLI/npm 包、内部 profile 和更新安装包均须包含相同公共架构。应用启动把资源根传给各进程，不依赖源码目录存在；应用更新保留用户安装和启用状态。

生成的 Extension 资产如因受支持的加载方案仍需暂存副本，应为可重建构建输出，不能恢复成手工维护的第二份 Adapter 源码。

CI/CD、发布流程、数据库 schema、凭据、文件删除和 Git 回滚按仓库规范单独确认。开发先完成可审阅的实现与验证，不擅自执行这些操作。

## 同步实施顺序与验收

每一步在两个仓库同步推进，使用同一组公开占位 Fixture；内部资产验证仅留在内部。公共模块保持一致，差异通过配置注入。

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| 0 | 分支、入口盘点、设计和差异台账 | 不改变已有运行行为；明确未完成项 |
| 1 | 外部包浏览器加载原型、路径和包契约 | 真实 Chrome 验证；两种 Runtime 路由与权限不退化 |
| 2 | 注册表、安装状态与安装管理器 | 内置/用户/开发选择一致；升级失败与冲突可恢复 |
| 3 | CLI/Backend/扩展/UI/Skill 接入 | 同一快照发现和执行；缓存刷新与旧名称兼容 |
| 4 | 探索生成与任务恢复 | 新格式生成到用户工作区，隔离验证后安装，计划完整且无捕获值泄漏 |
| 5 | 资产和 Profile/打包迁移 | 两版安装产物一致遵守架构；公开包无内部资产；单独验收 Toolkit |
| 6 | 兼容退场与交付 | 真实端到端、平台验证和必要确认完成后清理旧目录 |

验证矩阵至少覆盖：Windows 路径及文件占用、macOS 路径和打包；内置/Hub/本地/生成/开发来源；首次安装/更新/降级/卸载/冲突/离线/中断；浏览器页面与后台 API、Toolkit；旧任务恢复与新任务；内外 profile 的资产和来源隔离。Backend/脚本有聚焦自动化测试，Renderer 改动通过单测与构建。公开自动化不包含敏感扫描或真实账号。

## 已接入的本地包与 Skill 命令

两个版本共用以下 v2 包入口，不需要连接 Hub：

```text
webcli adapter install --directory <package-directory>
webcli adapter develop <development-directory>
webcli adapter use <name> <builtin|user|development|disabled>
webcli adapter remove <name>
webcli adapter list --json
webcli adapter info <name> --json
webcli <name> help
webcli <name> <command-id> help
webcli adapter skill <name>
webcli install --skills <name> --target <skills-directory>
```

本地安装的降级、新增权限、来源切换分别使用 --allow-downgrade、--allow-permission-change、--change-source；--inactive 安装但不启用。移除仅作用于托管用户安装，恢复可用的同名内置包，不删除开发工作区或内置源码。

CLI 列表、详情、帮助和派生 Skill 使用同一有效目录；同名旧副本不会因停用、损坏或移除重新出现。旧格式兼容测试使用隔离的空 v2 目录；新版优先级由临时包集成测试独立验证，不能据旧格式测试通过宣称旧命令别名或后台 API 已完成迁移。

派生 Skill 包含来源、Profile、版本、摘要、完整输入 Schema、写命令确认要求，以及有效包可选的 `guidance.md` 人工指导。`manifest.discovery_terms` 提供额外发现词；具体契约见 `docs/adapter_guidance.md`。文件写在目标 Skill 目录，不写回包。刷新只更新归属与内容摘要均匹配的生成文件；保留用户手写/修改及其他 Profile 的内容，并报告保留项。手动改名为 SKILL.md.disabled 的文件保持停用；停用、卸载或损坏的受管 Skill 在刷新时改为不可调用说明，不删除目录。v2 的 --generated/--regenerate 只输出当前派生说明；knowledge 不回退到旧目录，旧知识需逐条核对后迁入包指导或命令实现。

刷新可由 install --skills 显式触发；桌面站点切换会等待刷新，模型每轮开始前也刷新托管 Skill。历史 Skill 回放同时验证文件内容摘要与当前包摘要；无归属标记的同名旧文件保留，但不作为当前托管包的自动索引或历史说明。CLI 安装变化的主动 UI 通知、其他正在运行的模型回合及生成任务仍需接通，不能认为安装后全部消费者已自动同步。
