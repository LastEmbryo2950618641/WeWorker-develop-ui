# 客户端聊天复用 WebCLI：活动演示目标与交接

更新：2026-10-18。状态：**共享入口已接入，开发客户端真实生成验收进行中，尚未完成闭环**。本文件承接用户的运营演示需求，优先于继续开发复杂能力。OpenCLI 全面对齐目标保持 paused，完整范围保留在 [能力台账](opencli_parity.md)，不得标为完成或自动恢复。

## 目标

在本机明确版本的 WeWorker 客户端中，用户用一句自然语言提出一个简单只读网站查询封装需求，由客户端聊天 Agent 使用与外部 Agent 相同的 WebCLI 探索能力和 Skill，完成观察、编写 Adapter、真实验证、审阅安装，并在后续聊天中直接调用。以 GLM 当前成员的 5 小时和每周额度为真实站点验收对象；准备完成后，后台查询无需打开 GLM 业务页。

“一句话”指用户提供业务目标，不需手写接口、代码、计划 JSON 或终端命令；正常登录、选择明确的账号上下文以及已有策略要求的安装确认可以保留。不是承诺任意网站、零准备或零确认。客户端配置的模型负责理解和编写，WebCLI 提供确定性操作，不另建第二套探索 Agent 或要求额外模型 Key。

## 实现范围与顺序

1. **核对与复用。** 先读 AGENTS.md、ROADMAP.md、本文件、GLM 报告、后台探索说明，以及交接顶部/末尾。核对实际客户端聊天、权限模式、CLI 路径、Bridge/profile、Skill 同步和 Adapter 数据根。现有 full 模式可执行 WebCLI；不为演示放宽其他权限模式。
2. **统一调用路径。** 让聊天 Agent 发现并使用 `webcli-api-exploration` 与现有 browser/基础 Skill，通过通用 CLI 执行入口调用 `exploration.*`。探索算法、任务状态、验证、审阅、安装、修复仍由 WebCLI/Bridge 提供，不复制实现，不逐命令维护另一套业务工具。处理旧聊天工具竞争，兼容必要历史入口；暂不重做独立 API 探索页面。
3. **连接客户端状态。** 新包安装后同一客户端与后续聊天可发现最新命令和 Skill；保持同一 profile、安装目录与权限来源，避免安装成功但客户端看不到。复用已有等待/取消/错误通道，运行中不把 collecting/validating 当作完成。旧组件能力不足时给出具体升级提示，不退回页面验证冒充后台通过。
4. **保持后台能力。** 保留 runtime/execution/鉴权与准确权限，支持显式准备后后台查询；页面命令继续按自己的真实依赖执行。开源/内部使用同一架构，差别留在 Adapter，不添加 GLM 专用核心分支或复制内部代码。
5. **验收并整理演示。** 聚焦自动化、必要回归、实际客户端对话、匹配构建资源与演示步骤齐备后保存本地检查点。完成本目标后停止，不自动恢复全面对齐。

## 完成标准

以下全部有证据，才可标记本目标完成：

- 在用户指定的客户端验收对话输入自然语言封装请求，Agent 自行读取共享 Skill、核对登录/上下文、观察来源、编写参数和返回字段、提交真实 cases、验证及审阅安装；不由外部 Codex 手工代写 Adapter 后冒充客户端生成。
- 有一次干净生成流程的证据。当前 GLM 包可作回归参考和演示备用，但直接调用现成包不等于生成成功。先设计不删除/覆盖现有已验包的隔离验收方式；若确需替换已有包，先明确比较和审阅，不能默认为已授权再次删除。
- 真实 GLM 查询支持 5h/week/all，输出当前成员百分比和可用重置时间；缺失时间明确为 null，不能以 HTTP 200、非空或回显输入代替业务断言。真实结果只用于用户当前查询，不进入公开仓库、fixture 或交接文档。
- 准备后关闭任务自建的业务页，再从客户端发出自然语言查询并重复调用，确认后台 Runner、无页面补读/新页、结果有效；用户原有页面不擅自关闭。若要证明所有 GLM 页为零，使用用户指定环境或取得对应关闭授权。
- 后续客户端聊天能发现并调用安装结果，Bridge 重连或客户端重启后至少完成一次重复查询。先核对进程归属和已有授权，不重启未知服务；未覆盖的冷启动/登录恢复明确列出。
- 使用公开占位的只读列表夹具测试通用入口、Skill/资源路径、安装发现、权限和错误分支，确保没有把 GLM 写死进客户端。后台 Adapter 和现有页面/HTTP/Toolkit 调用边界不退化。
- Backend/脚本改动有聚焦测试；若改 Renderer，完成对应测试、build 与语法检查；改生命周期则按 AGENTS 完成相应生命周期验收。核对客户端真实使用的 CLI/Bridge/扩展/Skill 与源码版本一致，不能只跑源码 CLI 就声称桌面包已通过。
- 提供简短演示说明：启动哪个本地客户端构建、加载哪个扩展、登录与准备条件、用户说哪句话、预期输出、失败如何恢复；记录实际耗时和所需用户交互，不预先承诺生成时长。仅已有包调用可作为明确标注的备用演示，不替代从零生成验收。

## 当前实施与实测记录

- 普通聊天的旧探索 MCP 工具已移除，独立探索 UI 与历史任务保留。full 模式使用同分发 WebCLI 与三个共享 Skill；no_bash/qa_only 未放宽。每轮 SDK 发现前同步资源，内容摘要变化会重建会话，安装后仍用既有 Adapter catalog/事件同步。
- 后台命令按 runtime/execution 直接调用，无需同时带旧 mode=direct。缺登录/缓存执行显式准备，HTTP、页面和 Toolkit 维持各自运行时。
- 修复桌面开发 profile 缺省 legacy 字段、纯用户包 disabled 后桌面 legacy 回退，以及开发 CLI/Bridge 定位到不完整扩展资源导致 HTTP 校验 ENOENT。新增 @types/yauzl 仅为现有 ZIP 模块类型检查补齐类型。
- 验收使用本分支 WeWorker 1.1.0 开发客户端、当前客户端模型、Chrome 155.0.8059.80/扩展 1.1.0、独立 Adapter/host-data 目录。默认根已有 GLM 包保留，尚未用它代替生成。
- 第一轮模型余额不足，用户自行切换模型；下一轮误将模型凭据用于网站 AUTH_API，主动停止并补通用凭据/服务规则。后续从空目录实际探索、写草稿时发现开发包 HTTP 校验资源路径缺失，修复后重试；模型仍未先确认鉴权和字段语义，反复改断言，因此停止而未计为成功。共享 Skill 已前置来源、Cookie/请求头转换、字段映射与有效 cases 的要求，新聊天正在重新验收。
- 后续真实客户端观察发现 `browser.network all=true` 返回的业务请求，在按 key 读取 detail 时再次套用默认流量过滤，误报 `NETWORK_ENTRY_EXPIRED`。已修复为明确 detail key 不重复应用展示过滤，保留标签身份、实际捕获存在性及敏感字段脱敏；扩展 network/events 11 项、Chromium 1217 CLI＋Bridge 双打包专项 3 项通过。用户手动重载匹配扩展后，客户端实际读取额度详情成功并继续生成；这一步尚不等于安装或后台查询验收通过。
- 后台实测又暴露 helper 契约文档不完整与预览异常分类缺失。Skill 已补准确的 Cookie 集合、storage value、fetch 参数/返回值及逐选项 cases；预览只返回固定公开错误分类，任意 code/message/details 继续屏蔽。聚焦 2 文件/45 项、helper 11 项和 Chromium 1217 双打包后台专项 8 项通过，后者覆盖无页登录缺失与服务端 401 分类及敏感文本不外泄；不是实际账号登录恢复验证。源码/打包 Skill 各 4 项通过，客户端后续生成仍在验收。
- 当前聚焦证据：Backend 13 文件/96 项和 typecheck，WebCLI 路径/HTTP 4 文件/81 项，Electron 环境 7 项，桌面 HTTP 校验实际 bundle 2 项，双打包 HTTP 24 项，双打包 Chromium 后台专项 8 项、随包 Skill 4 项通过。Renderer 未改，构建通过；CLI/Bridge/Backend 构建通过，既有三个列映射资源缺失 warning 保留。这些自动化结果不替代下面待完成的客户端实站闭环。
