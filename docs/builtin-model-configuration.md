# 内置模型配置

内置模型通过构建 Profile 注册，供用户在模型设置中选择、启用和检测连接。地址、模型和鉴权由应用提供方管理，用户不能通过普通供应商保存接口修改内置模型。

## 公共构建

公共 Profile 包含两个内置模型的非敏感元数据。Backend 在运行时读取 `WEWORKER_BUILTIN_API_KEY` 和 `WEWORKER_BUILTIN_DEV_API_KEY`，不从 Renderer、构建常量或源码读取凭据。不提供真实值时，模型设置仍显示内置卡片，但“使用”和“测试连通性”禁用，并显示服务尚未配置的说明。

将该变量注入启动桌面应用的进程环境即可供 Backend 使用。构建时设置变量不会把凭据打入安装包；安装后的应用仍需由部署环境提供该变量。不得把真实值写入仓库、构建 Profile、示例脚本或命令日志。

激活仅持久化供应商选择和公开模型标识，运行时地址与凭据不会写入用户设置文件。后续保存其他设置、重新加载设置或切换供应商时仍按此规则处理；凭据缺失时不复用旧保存值或其他供应商的 Key。

公共构建继续保留原来的默认供应商，不自动替换已有模型选择。此功能恢复不等于已经部署免费模型服务。

## 开发内置模型

`builtin_dev` 的卡片和模型元数据会随公共构建分发，但其服务地址不进入 Profile。部署该模型时，启动应用的环境还需要提供 `WEWORKER_BUILTIN_DEV_BASE_URL` 和 `WEWORKER_BUILTIN_DEV_API_KEY`。地址必须是完整的 HTTP 或 HTTPS 基础地址；模型使用 Anthropic Messages 兼容接口。

`builtin` 使用 Bearer Token；`builtin_dev` 使用 API Key。两个运行时凭据和开发服务地址均不得写入仓库、构建 Profile、示例脚本或命令日志。
