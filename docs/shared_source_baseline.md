# 两仓共享源码基线

更新：2026-09-23。

公开版与内部版采用同一套通用产品逻辑。内部网站 Adapter、内部查询路由、部署地址、Provider 配置及发布身份保留在内部资产或 Profile 配置中。不能以公开版功能或内部版功能为由，长期保留两套通用实现。

## 本轮同步

- 客户端 API 探索：五步进度、捕获计时、任务恢复、交互问题、Agent 模式选择、保留证据后重试分析，以及模型上下文转发。
- 捕获证据隔离：持久记忆及生成输入保留结构信息，避免保存响应原文。
- Agent、工具策略、工作目录、执行 timing、CLI JSON 输出、网站探索agent的现有通用调试与发布流程双向合并。
- Renderer 共享源文件一致；部署链接和内部路由别名移到独立 JSON 配置。
- AdapterHub 与 Markdown 输出能力共享；Hub 默认地址由独立 Profile 指定，公开版需要显式配置地址。
- 两版统一使用 Backend 固定依赖中的 Claude Code 原生程序；上游安装器在 Windows/macOS 均使用 `bin/claude.exe`，最终打包仍检查原生格式、架构和权限。
- 公开网站 Adapter 同步到内部版，内部 effective Profile 为 38 个 v2 包、0 个旧包。经用户确认删除两份被正式命令替代的掘金草稿文件。
- 经用户确认，同步访问统计表、索引及 PV/UV 接口；仅用临时数据库测试，未迁移线上数据库。

## 一致性检查

运行 `node scripts/check-shared-parity.mjs <另一个仓库目录>`。

`scripts/shared-core-files.json` 明确列出共享运行时与公开 Adapter 源码；缺失、内容差异均失败，仅忽略 CRLF/LF 差异。该清单目前覆盖 527 个文件，不代表所有历史文档、测试、发布流程都逐字相同。

有意分离的配置包括 Renderer deployment/route-aliases、AdapterHub Profile、Provider registry、更新与下载地址、指标服务部署配置、网站探索agent模型配置、构建 Profile 与内部业务资产。Service Worker 仍保留内部登录业务分支，公共捕获、生成、托管执行和响应分发逻辑已同步。

依赖变更：公开 WebCLI 补充 `fflate` 以支持 Hub 包处理；内部 Renderer 补充 Ant Design 依赖以承载共享探索界面；桌面构建依赖对齐，移除公开根目录重复 Claude Code 依赖，使用 Backend 固定版本。相应 lockfile 已更新。
